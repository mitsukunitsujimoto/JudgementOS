# JudgmentOS — ブランドガイド

## 建付け（Version 1.3 · 単純形）

対外説明も画面も、この三段に揃える。用語は **判断基準** に統一する（価値基準とは言わない）。

1. **テーマ**: AIとどう向き合うか  
2. **目的**: 自分の判断基準を明確にすること  
3. **手段**: 判断基準が言葉になるために必要な問いに、答えていく（答えは出さない）

問いは「良い質問一覧」でも診断でもない。**判断基準を言語化するための問い**である。

成功の実感は便利さではない。

- 判断基準が明確になった  
- 最初は言葉になっていなかった本当の目的にたどり着いた  
- 人やAIの提案に対する自分の問い返し方が変わった  

重要性の度合いに関わらず、判断の場面が対象。日常の提案・AIの答えを受けた瞬間の問い返しも含む。

## ブランド体験（最優先）

JudgmentOS を開いた瞬間、**「これはChatGPTではない」** と感じること。

OS は入力から始まらない。**世界観から始まる。**

### 最初の画面（Version 1.3 · モニター）

トップは建付けの三段が一瞬で分かること。思想語彙より **使ってみたい** を優先する。「判断文脈」は体験の途中で紹介する。

```
JudgmentOS
AIと向き合うための思考OS

AIに解決策を聞く前に、
自分の判断基準を言葉にします。

答えを出すツールではありません。
判断基準が明確になるために必要な問いに、
答えていく場所です。

【判断基準を言葉にする】

判断を行う場面で、その重要性の度合いに関わらず、
自分の判断基準を明らかにしましょう。
```

体験中（置いた考えを見た瞬間）で自然に紹介する：

> JudgmentOSでは、これを判断文脈と呼びます。

### 核（Version 1.3）

**JudgmentOSは、AIと向き合うために、自分自身の判断基準を言葉にする思考OSである。**

価値はAIの回答ではない。必要な問いを通って判断文脈が育ち、自分の判断基準が更新されること。

順序は常に：本人 → 判断文脈 →（必要なら）問い → 文脈の更新 → 判断基準の言語化。

成功とは便利さではない。「AIの答えが変わった」ではなく、「自分の判断基準が変わった」と実感すること。

循環（B主経路）: 考えている → 論点を判定 → 振り返る（文脈を残す → 判断基準を未来の自分へ残す）  
詳細: `docs/judgmentos-b-policy.md`

### 体験の流れ · Version 1.4（考えている＝6問）

旧フロー（気になること〜ギャップ問い）は `judgmentos-v12.legacy.js` に保管。`?flow=legacy` で切替可。

```
考えている
  ① いま判断しようとしていること（入口では狭くてよい。掘り下げで「本当に問うべき判断」に変わりうる）
  ② 背景（この判断が必要な理由）
  ③ 本来実現したいこと（施策のKPIではなく、経営者として向かいたい姿）
  ④ 守りたいもの・崩したくないもの
  映し返し（本来実現 × 守る）
  ⑤ いちばん大切にしたいこと →（任意）譲れない／できれば
  ⑥ 重み・覚悟
  → 判断文脈を確認
  ↓
AIへ渡す（外のAIに、番号付きの論点形式で返させる。最適案は求めない）
  ↓
AIから戻る（論点を貼る → 採否する。作文3問はしない）
  ↓
①の更新：本当に問うべき判断の候補の採否＋「最初の判断は、いまも同じか」
  ※B方式（モニターで主経路化）: 方針は docs/judgmentos-b-policy.md
    ナビ想定: 考えている → 論点を判定 → 振り返る（論点提示はJOS内蔵。Aは非常口）
    AIは答えではなく、振り返りと問いの更新のための論点を掘り起こす
  ↓
育てる／振り返る（渡す前／後を見比べ、判断基準と本当の目的を未来の自分へ残す）
  ↓
振り返り欄（①最初の私／②今の私／③判断基準／④本当の目的）
  ↓
余韻（次の問い返しへの一文）
```

問い画面は読むだけで終わらせない。気づきを一文残し、それを見ながら判断文脈を更新する。

V1.3 のクライマックスは、**入力画面ではなく変化を振り返る画面**である。「自分は何が変わったのか」を言葉にし、未来の自分へ残す。「問い返す型」は標準フローには含めない。

トレードオフは独立の問いではない。③と④を並べるだけ。命名しない。

### 画面を閉じる瞬間

持ち帰るものは **AIの答えではない。あなた自身の判断基準** である。

### モニター招待（アクセス）

- 招待コードは `output/js/judgmentos-invite-codes.js` の配列で管理する（追加・停止・コード変更が容易）
- 初回のみコード＋名前（ニックネーム可）。以降はブラウザに保存
- 保存データ（判断文脈・判断基準）は名前と招待IDに紐づく
- 利用回数・利用日時は `judgmentos.v13.access` の `useCount` / `usageLog` に蓄積（将来の集計用）
- 開発確認は `?dev=1` でゲートをスキップできる

## 共通思想（講演 · LinkedIn · 書籍 · プログラム共通）

> AIは最適な答えを示すことはできる。  
> しかしどの未来を目指すかは決められない。

この一文は JudgmentOS の思想そのもの。画面の最初か最後に必ず表示する。

## 使命

AI を賢くすることではない。

**経営者が、昨日より深く考えられるようになること。**

## JudgmentOS とは何か

- 答えを出すツールではない
- 問いを作るツールでもない
- AI へ相談するツールでもない

**経営者が、自分自身の意思決定を映し、未来を決めるための OS。**

## 三層構造（開発者向け · 体験後に理解される）

```
JudgmentOS                    ← 判断プロセス全体を支える OS
│  Decision Context Mirror     ← 中核機能
│    └ 問いの鏡                ← 入口ワークスペース
```

## 判断の一直線

```
Premise → Decision Context → Question → AI → Judgment Criteria
```

主役は **本人の判断基準の更新**。Decision Context は Judgment を支える構造。

## 言葉の使い方

| 場面 | 表記 |
|------|------|
| ランディング CTA | **判断基準を言葉にする** |
| 入口 | **気になっていること**（判断から始めない。決裁だけでなく、今日受けた提案・AIの答えでも可） |
| AIへ渡すもの | テーマ · 実現 · 守る · 制約 · 本人の言葉の映し返し の5点のみ |
| 締め | **判断基準**（AI回答の保存ではない）＋次の問い返しへの一文 |
| 禁止 | 「トレードオフ」「診断」「分析」「命名」「価値基準」（対外は判断基準に統一） |
| 最初から | 「文脈を映す」は使わない。意思は体験の中で言語化する |

## UI 表記ルール
