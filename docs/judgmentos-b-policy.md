# JudgmentOS · B方式 方針メモ

合意日: 2026-08-02  
対象: モニター期間（目安3か月）に実装する「薄いB」まで。それ以上はモニター後に別分岐として決める。

関連: `docs/JUDGMENT_OS_BRAND.md` / `docs/judgmentos-monitor-followup.md`  
図解（A時点の全体像）: https://diagram-judgmentos-how-it-works.surge.sh

用語: 画面・対外では **論点**（旧称「仮説」）。内部API名 `generate-hypotheses` 等は互換のため残してよい。

---

## 1. AとBの違い

| | A方式（いま／非常口） | B方式（モニターで主経路にする） |
|---|---|---|
| AIの置き場 | JOSの**外**（ChatGPT等） | JOSの**中**（モデル接続） |
| 手作業 | コピー → 外で論点 → また貼る | 「論点を示す」→ その場で採否 |
| 思想 | 同じ（答えは出さない／決めるのは本人） | 同じ |

- **AはAI未内蔵。** 渡す型と採否の場だけをJOSが担う。  
- **Bは論点提示だけを内蔵する。** ChatGPTを丸ごと入れるのではない。  
- Bの目的は「モデルが賢い」ことより、**往復のない体験で、整理台帳ではないと分かること**。  
- AIは答えを出さない。**気づいていなかった論点を掘り起こし、採否 → 振り返り → 問いの更新**へ渡す。

---

## 2. 論点の定義（対外・画面共通）

**論点とは、判断文脈を前提に掘り起こした「採否の単位」であり、結論でも最適案でもない。**  
本人が採る／捨てる／直すための材料。振り返りと問いの更新につながる。

画面用の一文:

> 論点は答えではありません。気づいていなかった点を、いま言葉にした内容に照らして採る／捨てるためのものです。あとで振り返り、最初の判断を見直す材料になります。

| 論点である | 論点ではない |
|---|---|
| 「ここを考えていなかったのでは」という材料 | 「やるべきはこれ」という最適案・指示 |
| 判断文脈（目的・守る等）の内側で立つ | 文脈を無視した一般論カタログ |
| 採否できる単位（番号で分かれる） | 長い作文・総合レポート |
| ①が「本当に問うべき判断」に変わる候補も含みうる | 本人の代わりに決めた結論 |
| AIの解釈・見立ての押しつけ | （見立て・仮説という言葉は使わない） |

---

## 3. フローとナビ（B主経路）

```
考えている
  ↓
論点を判定   ← 文脈確定 → 内蔵で論点提示 → 採否・①の更新
  ↓
振り返る     ← 変化を言葉にし、判断基準・本当の目的を未来の自分へ残す
```

- 旧称「AIへ渡す／AIから戻る」は **論点を判定** に統合する。  
- 旧称「育てる」は **振り返る** に改名する。  
  - 意味: AIや事業を伸ばすことではない。  
  - **今回の判断で見えた変化を言葉にし、判断基準と本当の目的を未来の自分へ残すこと。**

### 判断文脈の「確定」

- ①〜⑥等を経て判断文脈がまとまっただけでは未確定（下書き）。  
- **ユーザーが内蔵AIへ渡す操作（「論点を示す」等）をしたとき** に、その時点の文脈を確定扱いで送る。  
- 確定の主語はシステム自動ではなく、渡す意思を持ったユーザー。

### 文脈をあとから直したとき

1. 判断文脈はいつでも直せる。  
2. 直したあと、既存の論点と採否は **無効（古い）**。  
3. 進むには **「論点を出し直す」** が必要（自動再生成はしない）。  
4. 旧論点は履歴として残してよいが、採否の正本にはしない。

---

## 4. 内蔵AIに許す範囲／許さない範囲

### 許す（B初版）

- 判断文脈確定後に、**番号付き論点**を出す。  
- **①が「本当に問うべき判断」に変わる候補**を出してよい。  
- 最適案・一つの正解は出さない（Aの依頼文と同じ型）。

### 許さない（B初版・モニター中）

- ①〜⑥の下書き代筆  
- 最適案の提示・ランキング  
- チャットでの壁打ち  
- 判断文脈の勝手な書き換え  
- 無制限再生成  

将来のチャット化・無制限再生成は **あり得るが未決の別プロダクト／別プラン**。  
やるならモード分離・料金・成功定義をセットで決め直す。標準Bを侵食しない。

---

## 5. 主経路と非常口

- **平常時の主経路はB。**  
- **Aは非常口**（平常時は並べて選ばせない）。出すタイミング例:  
  - セキュリティポリシーに同意しない  
  - API障害・上限超過・タイムアウト  
  - 「自分のAIを使う」を明示選択  

### 失敗時

- 失敗を隠さない（「いまは論点を示せません」）。  
- 自動リトライは **1回まで**。  
- その場で非常口Aを案内する。

---

## 6. 回数上限（モニター〜B初版）

| 単位 | 上限 |
|---|---|
| 1つの判断（同じ判断文脈の系列） | 論点提示 **3回**（初回1＋出し直し2） |
| 1人あたり／日 | **10回** |

使い切ったら: 文脈を直す／非常口A／日をまたぐ、のいずれか。自動で無制限にはしない。  
上限の主目的は節約より、**「気に入るまで回す」体験を防ぐこと**。

## 7. 費用・モデル（モニター）

- **負担:** APIアカウントのクレジットカードへ従量請求（モニター個人には請求しない）。ChatGPT Plusとは別。  
- **モデル:** **GPT-4o**（モニター期間）。  
- **予算感:** 3か月で **約3万円** まで見ておけば余裕。API側に月次ハードリミット（目安 **月1万円**）を付ける。  
- **商用化時:** 無制限をあなたが永久負担するのは非現実的。価格に含めた利用枠＋超過従量等は後決。  
- OpenAI直かAzure等経由かは **未決**（実装時に選ぶ）。

## 8. セキュリティ・同意

- 初回に **短いセキュリティ明示**（画面1枚）。長い条文はリンクの奥でよい。  
- 伝える要点:  
  1. **いつ送るか** — 「論点を示す」を押したときだけ  
  2. **何に使うか** — 論点提示のみ  
  3. **拒めるか** — 不同意ならA固定（考えている〜コピー往復は可、内蔵AIには送らない）  
- **同意 → B解禁／不同意 → A固定。** JOS全体を拒否する必要はない。  
- プロンプトには生成に必要な文脈だけ。学習利用オフが選べる設定を使う。ログに本文を残しすぎない。  

### セキュリティ短文（確定・画面1枚）

**タイトル:** 論点提示のためのデータの扱い

**本文:**

あなたが書いた内容は、「論点を示す」と押したときだけ、論点を提示するために外部のAIサービスへ送られます。  
用途は論点の提示のみです。JudgmentOSは、AIの答えを保存するツールではなく、あなたの判断基準を残すツールです。

送りたくない場合は「自分のAIを使う」を選んでください。考えている〜論点を選ぶ流れはそのまま使えます（この画面で論点を出す機能だけ使いません）。

**ボタン:**
- 同意して進む → B解禁  
- 自分のAIを使う（送らない） → A固定  

※詳細な条文が必要になったら、この画面からリンクで添える（モニター初版は短文のみ）。

## 9. モニター期間のスコープ上限

### やる（薄いB）

1. Bを主経路にする（上記ナビ）  
2. GPT-4o・主催者負担・回数上限  
3. 短いセキュリティ明示（不同意はA）  
4. 文脈修正 → 論点無効 → 明示の出し直し  
5. 失敗時の正直な表示＋非常口A  
6. 招待はまず少数（目安 **5人**）。動いてから増やしてよい  

### やらない（モニター中）

- チャット化・無制限再生成  
- ①〜⑥のAI代筆  
- 組織機能・利用者課金・本格法務固め  
- モデル自動切替や過度な品質競争  
- 「論点が神がかっているか」を成功指標にすること  

### モニターの成功（既存方針と同一）

便利さや完走回数ではなく、本人の言葉:

- 判断基準が明確になった  
- 本当の目的にたどり着いた  
- 人／AI提案への問い返しが変わった  

目安: 異なる人物から変化実感の言葉が約5件。詳細は `docs/judgmentos-monitor-followup.md`。

## 11. やらないことの再掲（思想）

- JudgmentOSは答えツールではない。  
- 持ち帰るものはAIの答えではなく、**判断基準**。  
- 「売上20％より高い問いが常に正しい」と誘導しない。本当に問うべき判断への変化は起きても起きなくてもよい。  
- 入口の問いが自分の判断として妥当かを言葉にする道具である。
